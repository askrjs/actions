# Qualifying the unpublished 0.5.0 graph

The helper reconstructs 18 reviewed archives from immutable public source
commits and serves those exact bytes on a GET-only loopback registry, allowing
each repository's ordinary npm ci and existing complete gate to run before npm
publication. It is specific to this release, not a general registry or release
framework. No npm token, cross-repository artifact credential, external hosting
or committed archive is needed. Permission stays `contents: read`.

## Immutable inputs and sequence

1. Review/merge helper source commit H independently. Its tests use synthetic
   packages; they do not qualify the final 18-package graph.
2. Finish feature source, 0.5.0 versions/ranges and portable locks. Build/test/pack
   each package normally with Node 24.21.0/npm 12.0.1. Freeze all 18 source commits P,
   source trees, package/lock hashes and archive SHA512 values. Push those reviewed
   source commits to public branches before using the helper.
3. Add `fixtures/0.5.0-candidate-graph.json` in a separate Actions commit M. Use the
   schema/template, complete=true and all 18 real coordinates. Record its literal
   SHA256; incomplete/template values are rejected. The manifest has no reference
   to itself and is absent from the 18 builder source heads.
4. Each caller C pins helper H by 40-character commit and manifest M by 40-character
   commit plus exact SHA256. Add only workflow YAML to the frozen P source.
   Prepare runs before normal current-repository npm ci; verify-current follows
   the existing complete producer gate; cleanup runs under always().
5. Require exact native Linux/macOS/Windows reconstruction and existing complete
   current-repository gates. Record builder P and checked-out event C separately.
   No new archive digest may replace a mismatch. Full user review and explicit
   publication approval remain separate.

The frozen manifest accepts only the fixed 18 package/repository identities and
version 0.5.0 coordinates. Internal
ranges are 0.5.0 or >=0.5.0 <0.6.0; internal locks must use canonical public npm
URLs and immutable SHA512 integrity. Unknown candidates/old versions never fall
back to public 0.4. Complete dependency, development, optional and peer edges
must be acyclic for ordinary topological construction; resolve real dev cycles
in reviewed sources rather than adding install bypasses.

## Phases

| Phase          | Required placement                      | Behavior                                                                                                                                                                                                                                   |
| -------------- | --------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| prepare        | Before ordinary current npm ci          | Fetch/check separately frozen manifest and public exact versions; otherwise fetch all immutable P source commits, verify source hashes, normally ci/prepack in order, reject changed source/archive bytes and start the loopback registry. |
| verify-current | After producer's existing complete gate | Verify actual event checkout, tracked source cleanliness, workflow-only P→C delta and normal current prepack bytes equal the same reviewed SHA512; record both source identities.                                                          |
| cleanup        | always(), after prepare attempt         | Identity-check/stop the owned loopback process and restore scoped/unscoped registry/audit environment. Does not publish.                                                                                                                   |

All phases require the same manifest-ref and manifest-sha256. The helper fixes
Node 24.21.0/npm 12.0.1 for reproducible builder archives. Retain intentional runtime
floor/current matrices by restoring their test toolchain after prepare and
restoring the frozen builder toolchain before verify-current when necessary;
never silently replace an existing floor gate with the builder version.
Primary 0.5 package gates use Node 24.21.0/npm 12.0.1 explicitly. Repository
setup can prepend its bundled npm, so restore the helper's npm bin directory
after that setup and assert the actual versions before ordinary npm ci. The
helper restores npm again after its own Node setup for verify-current, including
the npm used by nested prepack lifecycle commands.

Prepare admits the 18 producers and exactly askrjs/askr-examples, askrjs/website,
askrjs/destroyer and askrjs/js-framework-benchmark. Consumer callers use prepare+cleanup around their existing
normal install/full gates; verify-current deliberately requires a producer
archive. Their exact event source and consumer assertions remain their own CI
ownership. Other repositories are rejected.

The benchmark admission supports its two first-party Askr owners through a
dedicated keyed/non-keyed qualification job with ordinary owner installs,
Vite+ builds and native behavior/identity checks. It does not alter the foreign
framework comparison matrix or turn the benchmark into a published producer.

Once all 18 public versions and archive bytes exactly match, prepare uses public
npm and skips reconstruction. It still verifies immutable public bytes and
verify-current still proves the current producer pack. This release-only wiring
is not an automatic new-version release mechanism; update/remove it when
authoring a later package version.

## Install, source and process ownership

Both NPM_CONFIG_REGISTRY and npm_config_@askrjs:registry point to the loopback URL.
The scoped setting matters because repository .npmrc can override an unscoped
registry. Automatic npm audit is off only while the GET-only fixture is active;
explicit audit gates must target public npm, which owns the advisory database.
There is no --force, --legacy-peer-deps, peer override, source link or package
manifest rewrite. App/package ci and prepack lifecycle scripts run normally.
The separate npm CLI bootstrap skips scripts only for the exact npm tool itself.

Each successfully verified builder drops only its owned node_modules after its
archive is registered. Artifacts, npm cache and source/proof/log files are kept
for the registry and diagnostics. Current repository dependencies are never
deleted. A failed builder keeps its failure evidence. Cleanup stops the owned
server, and never terminates a process whose identity does not match.

Third-party metadata/archive GETs go to public npm. Candidate metadata keeps
canonical public tarball URLs, so generated locks stay portable; npm's ordinary
registry mapping/cache owns transport. The fixture refuses writes and unknown
Askr versions. Browser/service-worker app origins are unaffected.

Frozen builder checkouts explicitly disable autocrlf. Caller checkout steps
need the same per-step GIT_CONFIG_COUNT=1, GIT_CONFIG_KEY_0=core.autocrlf,
GIT_CONFIG_VALUE_0=false guard when packaged text lacks explicit LF attributes.
It changes no global config and preserves explicit repository EOL attributes.
Native output/permissions/line-ending drift must fail the expected archive hash.

Preserve helper receipts from runner.temp/askr-0.5-candidate-* (JSON/log files;
archives only when specifically needed by the reviewed publication flow).
Normal complete gates, installed consumer/native browser/type tests, explicit
audits and protected publication permissions remain repository-owned. Baseline
benchmark installs intentionally consuming 0.4 need explicit public scoped and
unscoped registry environment; do not weaken candidate-only lookup for them.

## Qualification limits

Local fixtures prove strict manifest admission, ordinary progressive ci/prepack,
physical installed peers, canonical locks, source/byte rejection, GET-only
transport, supported consumers, per-builder dependency cleanup and detached
process cleanup. They do not establish all 18 final archives or actual hosted
composite execution. Native three-OS fixture CI is required, followed by actual
complete g2 public-source reconstruction/current full gates on those platforms.
No source review or fixture success authorizes publication.
